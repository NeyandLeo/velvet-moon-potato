# 猫眼电影票监控助手

这是一个本地 WebUI 工具。它使用可见、可被 Playwright 控制的 Chromium 浏览器打开猫眼 H5 页面，识别影片、影院、观影日期、场次时间、影厅、语言格式和可售状态。它还能保存近期排片快照、汇总可能使用的影厅，并为每个影厅配置多组有优先级的座位组合。

登录、短信验证码和人机验证必须人工完成。本项目不伪造猫眼接口签名、不绕过验证码，也不直接调用创建订单或支付接口。

**验收状态（2026-09-04）：真实排片筛选、登录后自动选座、候选组切换及页面总价读取已验证；锁座和创建订单尚未进行真实提交验收。** 只有页面能明确定位座位且核对已选状态和总价时，才尝试提交；不兼容时停在猫眼供人工操作。按用户要求，默认启用“自动提交订单”：不再弹总价确认，选座核对后直接尝试生成待支付订单。支付始终人工完成，可取消勾选恢复二次确认。

## 已验证的猫眼链路

- 影片列表：`https://i.maoyan.com/cinemas#movie`
- 影片对应影院：`/mtrade/cinema/movie?movieId=...`
- 影院排片页：`/mtrade/cinema/cinema?cinemaId=...&movieId=...&date=...`
- 排片响应：由猫眼页面自己签名和请求的 `cinema/cinema/shows.json`
- 选座页：`/mtrade/cinema/seat?seqNo=...`

当前“奥德赛”的猫眼 `movieId` 为 `1545360`。这个 ID 是在 2026-09-04 从猫眼当前页面确认的，未来页面数据变化时以猫眼页面为准。

页面顶部显示后台版本、启动时间和 PID。**关闭猫眼窗口或刷新 WebUI 不等于重启 Python 后台。** 更新代码后，要在运行服务的终端 Ctrl+C，再执行 `./start.sh`，然后刷新 WebUI。5000 端口已占用时新进程会提示旧后台尚在运行，不会悄悄复用它。

新版监听浏览器关闭事件：关闭后停止当前操作、清除失效的浏览器引用和待确认状态；再次点击“打开登录浏览器”会复用本地资料重新启动 Chrome。后台的登录状态轮询不会擅自重开窗口，也不会自动恢复监控或重试下单。

## 正确使用顺序

1. 点击“打开登录浏览器”。
2. 在弹出的 Chrome 中手动输入手机号和短信验证码并登录；不要关闭这个 Chrome。
3. 填写影院完整名称和观影日期，点击“侦察近期排片”。
4. 根据识别到的所有可能影厅分别填写座位候选组，例如 `8排 9,10`、`8排 11,12`、`7排 9,10`。同一影厅各组票数必须相同，最多 5 组，每组最多 6 张。
5. 填写开始监控时间、场次范围和影厅优先级，点击“开始监控”。
6. 匹配成功后，工具会打开选座页并按顺序尝试候选组；任何定位不唯一或结构不兼容都会降级为人工选座。
7. 默认勾选“自动提交订单”：程序核对预设座位和可读取的实际总价后，直接尝试点击猫眼确认选座控件，不再等待总价确认。取消勾选时才显示人工确认，确认有效期 2 分钟。此操作可能创建待支付订单，请在开始监控前检查你的配置。
8. 点击后显示“请核对订单结果”，不是购票成功。程序不会自动重试；请在猫眼检查是否生成待支付订单，并人工支付。结果不明时不要重复下单。核对完成后可点“结束本次流程”，这不会取消猫眼订单。

影院名过于宽泛并匹配到多个结果时，程序会停止，避免选错。可以在高级设置中填写 `cinemaId` 消除歧义。名称须与实际排片名称一致；填写 ID 时也会核对名称，防止修改电影名却沿用旧 ID。

## 筛选和排序

### 北京 / 上海本地影院菜单

任务配置顶部按“城市 → 行政区 → 影院”选择，名称、`cinemaId`、`cityId` 自动填写。可以按影院名、商场或地址关键词筛选；浏览器会记住上次选择。切换目标会清空页面上旧影院的影厅预设（已保存的历史预设仍保留）。目录外影院仍可手填。

- 2026-09-04 初始快照：北京 **328 家 / 16 个区**，上海 **379 家 / 16 个区**，均已读完该次猫眼公开列表并核对去重数量。
- 初始库为 `data/cinemas.json`；手动更新写入 `.runtime/cinemas.json`，优先使用更新库。只保存影院 ID、名称、地址、区划、来源和更新时间，不保存账户数据。
- 城市 ID 来自猫眼 [城市列表](https://i.maoyan.com/dianying/cities.json)；行政区来自 [北京区划筛选](https://i.maoyan.com/ajax/filterCinemas?ci=1)、[上海区划筛选](https://i.maoyan.com/ajax/filterCinemas?ci=10)。影院数据来自其公开 [北京目录](https://i.maoyan.com/ajax/cinemaList?cityId=1&offset=0&limit=20)、[上海目录](https://i.maoyan.com/ajax/cinemaList?cityId=10&offset=0&limit=20)。区划以地址开头匹配官方区名；不能确定的归入“待核实区划”，不猜测。
- 目录只表示猫眼当次接口收录，不保证所有营业影院或目标电影均可购票。停业、更名、新开影院会使快照过时；实际购票仍核对排片页上的影院身份。
- 展开“更新本地影院库”，点击“更新当前城市”。使用系统 `curl` 串行读取公开元数据，不登录、不用 Cookie、不签名、不创建订单。默认每 3 秒一页，间隔支持任意有限正数；设置小间隔不代表符合平台规则。需要系统已安装 `curl`（macOS 自带）。
- 与侦察、监控互斥；可停止。每城最多 100 页；超时、拒绝、验证、分页停滞或数量不完整时不重试、不覆盖旧城市目录。停止时当前已发送的请求最多约 20 秒结束。
- 影院目录不等于影厅清单：选影院后仍需“侦察近期排片”识别具体 IMAX / 杜比厅，再配置座位。不会按影院名称臆测影厅。

### 场次筛选

- “影厅优先级”按从左到右排序，例如 `IMAX, Dolby Cinema, CINITY`。默认只接受这些关键词匹配的厅；取消“不接受优先关键词以外的影厅”才会允许其他厅兜底。留空表示不限影厅。
- “排除关键词”可排除 `情侣厅`、`4D` 等。
- “语言/格式限制”会匹配影厅、语言和放映格式中的任意关键词。
- 影厅优先级相同时，优先选择更靠近所填时间范围中点的场次。
- 最高参考价使用排片响应里可直接读取的影城卡/参考价；未知参考价不会被过滤。它不是订单预算上限，最终实际总价必须在猫眼核对。

## 排片侦察与历史

- 从 `2026.09.04.5` 起，侦察汇总同一家影院当前响应中的**所有电影、所有排片日期（包含未来）**，不再只看目标电影，也不再截断到目标日。即使目标电影尚未开预售，也能用其他电影的排片发现候选影厅。
- “补充本地历史（目标日前天数）”只控制历史快照窗口：目标日前 1–14 天至目标日。实时响应中的日期无论早于或晚于这个窗口，都会保留。侦察和监控会把响应内全部电影、日期的快照保存到 `.runtime/schedule_history.json`，兼容原来只保存目标电影的历史文件。
- UI 展示本次返回的日期、影片数、场次数，逐日标注“当前响应 / 历史快照 / 当前+历史”。每个厅标注目标电影当前场次、其他影片备用候选或仅历史记录，以及格式、日期和影片名称。
- 当前记录按“影院 + 电影 + 日期”覆盖旧快照，重复场次去重。明确返回空排片的日期不会恢复成旧场次；同影院其他电影的历史仍可补充候选厅，不混入其他影院。
- 这只是本次网页响应可见的范围，不是对全网完整排片的保证。网站未返回、尚未公布或已下线且从未保存过的数据无法凭空获取；某厅放映其他电影或仅在历史出现，不代表目标电影将使用该厅。
- 扩大侦察仅改变候选影厅发现，不增加逐日期/逐影片刷页请求，也不改变购票筛选：监控仍只匹配指定电影、目标日期、时间、影厅偏好与座位预设。
- 快照仅含排片元数据，不保存账号、验证码或支付信息。

## 座位 fallback

- 每个影厅按名称精确匹配自己的座位预设，避免把一个厅的排/座号误用到另一个厅。
- 同一影厅可配置最多 5 组，严格按从上到下的优先级尝试；两张票的三组示例是 `8排 9,10`、`8排 11,12`、`7排 9,10`。
- `seat_adapter.py` 按真实 v8 响应的区域/行/座位结构映射 `.my-seat` 图片，核对页面排号顺序和每行元素数后才点击。过道占位计入位置；排号使用 `rowId`，不将布局索引 `rowNum` 当排号。
- 整行过道可能有空白、重复排号；只要该行全部为状态 0，就保留布局索引而不当成实体座位行。实体座位行仍须排号唯一。此前在这一步误报“排号缺失或重复”，导致读到数据也不点击，现已修复。
- 当前只自动处理单区域普通座位，且状态必须为 1（可售）。状态 2/3/4、情侣座或多区域会明确提示；不会把未知状态当可售。
- 旧版要求 `aria-selected`，但猫眼当前图片座位没有此属性，导致捕获座位数据后仍停下。新版逐个点击后读取猫眼实际“已选座位”列表核对，不再依赖不存在的属性。
- 确认控件也改为猫眼实际带价格的 `div[data-bid="b_212zq"]`，不再只寻找标准 button。WebUI 显示控件上的实际总价，确认时价格有变动就停止。该价格仍须由用户在猫眼核对。
- 部分点击失败或无法核实实际已选座位时，不反向点击、不自动换下一组，以免误改用户选择。
- 内部一次性令牌绑定选座页 URL、座位及实际总价；自动与人工模式共用同一校验和防重入逻辑。点击尝试前消费令牌，超时也不复用；自动模式不会弹出确认框，也不会自动付款。

页面明确区分“加载座位图”“正在选择预设座位”“等待确认”和“需要人工处理”。座位图监听覆盖登录重定向，最长等待响应 20 秒；某组不可用会说明具体排座号和原因。进入选座后失败不回到排片循环自动重试，防止重复点击。

适配依据：猫眼公开前端 [座位渲染组件](https://s0.pipi.cn/festatic/fe-trade/public/js/commons.febb5800.js) 与 [选座提交组件](https://s0.pipi.cn/festatic/fe-trade/public/js/51.0834369e.js)，以及本地真实运行日志中的 `img.my-seat` 结构。2026-09-04 21:06 已在清河 CGV 22:55 IMAX 场次验证：12 行布局、221 个实体座位；第一组 8排9座已售，成功切换第二组并读回 1排2座/1排3座，总价 208 元。该次测试关闭自动提交，没有创建订单。不能保证平台未来版本兼容。

选座适配失败时可保存 `.runtime/last-seat-diagnostics.json`：仅白名单座位布局字段、页面排号与元素数量，不含账号、验证码、Cookie 或完整请求/响应。

## 请求限制

### 付款提醒

页面顶部点击“开启桌面通知和声音”，允许浏览器通知，再点“测试提醒”确认声音和桌面通知能收到。每次刷新页面后需要重新点击按钮激活声音；通知权限一般由浏览器保留。

提交选座后（包括点击超时）发布“选座已提交，请立即核对并付款”提醒，显示影片、影院、场次、座位和选座总价。当前尚未验证真实订单创建，因此不会将提交尝试显示为抢票成功。页面突出显示提醒、修改标签页标题，并在声音激活后每 15 秒提示一次，直到点击“我已知晓，停止提醒”。可取消“循环提示音”静音。

提醒保存在 `.runtime/order-notification.json`，刷新/重启后仍保留，知晓操作不会改变订单状态或代表付款成功。页面显示提交后 15 分钟的参考时间，实际付款期限以猫眼为准。保持电脑唤醒、助手网页打开；浏览器后台节流、通知权限、静音或系统勿扰可能影响到达时间。本版为电脑端提醒，尚无手机推送。

`GET /api/notifications` 读取提醒；`POST /api/notifications/ack` 使用 `{"event_id":"当前提醒ID"}` 标记知晓。没有测试下单接口，“测试提醒”只触发浏览器通知及声音。

### 监控请求

- WebUI 和服务端接受任意大于 0 的有限数字作为刷新间隔，支持 0.2、0.5、1 秒等小数，不再强制 3 秒下限或 120 秒上限。
- 运行中修改间隔后点击“应用到运行中任务”，当前等待会使用新配置，不会触发并发刷新。页面展示有效间隔和预计下次刷新时间。
- 最长监控时间限制为 180 分钟。
- 普通连续读取失败按至少 5 秒的基准逐次退避，上限不低于用户设置的间隔；连续 5 次失败后停止。故障退避不会因设置很小的正常间隔而取消。
- HTTP 401/403/429、业务非成功响应、影院身份不匹配或验证页面会停止自动请求，人工检查后再启动。停止也会取消当前正在等待的浏览器操作，但不能撤回已发送的请求或订单。
- 间隔指上次页面读取完成后到下次读取之间的等待，不等于实际页面加载周期或全站 HTTP 请求数。程序始终串行，不并发刷新；页面资源仍由猫眼控制。降低间隔不代表平台允许自动化，请遵守实际平台限制。

## API

- `GET /api/cinemas`：离线读取本地城市、行政区和影院目录。
- `GET /api/cinemas/sync`：目录更新状态与进度（只访问本机）。
- `POST /api/cinemas/sync`：更新当前城市，JSON 如 `{"city_id": 10, "interval": 3}`。
- `POST /api/cinemas/stop`：取消目录更新，不影响已保存的数据，JSON `{}`。
- `POST /api/browser/login`：打开持久化登录浏览器。
- `GET /api/browser/login-state`：检查当前页面登录状态。
- `POST /api/analyze`：读取影院当前响应中的所有电影和所有排片日期（含未来），保存快照并合并本地历史，汇总候选影厅。
- `POST /api/start`：启动后台监控，立即返回 HTTP 202。
- `GET /api/status`：获取阶段、匹配场次和日志。
- `POST /api/settings/poll-interval`：运行中调频，JSON 如 `{"poll_interval": 10}`。
- `POST /api/order/confirm`：核对一次性 `confirmation_token` 和页面选座状态后尝试点击确认；响应 `order_verified: false`，不代表创建订单成功。
- `POST /api/stop`：请求停止任务。
- `GET /api/health`：服务健康检查。

所有 POST 必须使用 `Content-Type: application/json` 和 JSON 对象（停止用 `{}`）。本地服务拒绝跨站请求与未知 Host，只允许本机访问，请勿部署公网或配置反向代理公开此服务。`.runtime` 中浏览器资料含登录会话，不要上传或分享。

## 已知边界

- 猫眼会动态生成请求签名，因此程序只监听页面自己的正常响应，不把签名复制到独立 HTTP 客户端。
- 猫眼 H5 登录使用短信验证码，必须人工完成。
- 自动选座依赖猫眼当前座位响应和页面元素属性。若猫眼使用 Canvas 或更改字段，工具会安全降级到人工选座。
- WebUI 确认会点击猫眼页面的“确认选座/去结算”，这可能生成一个待支付订单；不会点击支付按钮。
- 猫眼改版后，页面选择器可能需要调整。排片解析主要依赖响应字段 `movies[].shows[].plist[]`，比旧版猜测 CSS 结构稳定。
